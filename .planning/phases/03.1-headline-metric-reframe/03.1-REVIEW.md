# Phase 03.1: Code Review Report

**Reviewed:** 2026-10-24
**Depth:** standard
**Files Reviewed:** 19
**Status:** issues_found

## Summary

Phase 03.1 replaced the per-head variant headline with "campaign-markets in market per quarter". It added `markets_per_campaign`, `formats_per_market` and `campaign_growth_share` (the route radio) to the model, a cost-per-campaign-market row, and brief-to-live time as a headline companion. The plumbing is consistent. Static figures match `compute()`. The 364 tests pass and `crosscheck` reports 0 failures. The route radio is allow-listed in both `parseHash` and `toCompute`, and the static maths and results tables have the same row counts as `RESULT_ROWS` and `mathsPresentation`.

The main defect is in what the new headline says. By construction, `campaign_markets` always equals the input multiplier. It is reported as "live" and "+100%" even when the model itself says review capacity is exceeded and the queue never clears. That contradicts section 07 of the page and the project's honesty constraint. The other findings are wording drift ("approved-live" is still used next to "approved"), a "flat headcount" claim that the model never checks, unvalidated marketing FTE, and a fallback for the default route that can silently drift.

## Critical Issues

### CR-01: Headline says 2x campaign-markets are "live" when the model says the review queue never clears

**File:** `site/js/model.js:430-432` (also `site/js/model.js:159-161`, `site/js/calc.js:108-111`, `test/model.test.js:220`)
**Issue:** `campaign_markets_per_year = campaigns × markets` is computed from the inputs and the multiplier only. It does not depend on review capacity, so `ratios.campaign_markets` is always exactly `multiplier`. When `review_capacity_exceeded` is true, `present()` still builds `lead = "...at 2x you have 100 campaign-markets live per quarter"` and then adds "but reviewers are over capacity ... brief-to-live time is unbounded". The results row still shows `100` and `+100%`, and the live chart still draws the 2x bar. Section 07 of the page says the opposite: "At 2x without the gate there is no brief-to-live time to show, because the queue never clears." So the page claims the work is in market while saying it can never go live. I reproduced this with `present({...defaults, auto2: 0.2}, ctx)`: "at 2x you have 100 campaign-markets live per quarter ... but reviewers are over capacity, at 110%". `test/model.test.js:220` locks the contradictory sentence in as golden output. This breaks the CLAUDE.md honesty constraint on the page's headline metric, at exactly the inputs where a CFO is probing the downside.
**Fix:** When over capacity, do not call the 2x campaign-markets live. Report them as demand, or cap them at what capacity allows.
```js
// model.js present()
const lead = over
  ? `With ${route}, 2x would mean ${cm} campaign-markets per quarter, but reviewers are over capacity, at ${z}, so that volume cannot go live and brief-to-live time is unbounded`
  : `With ${route}, at 2x you have ${cm} campaign-markets live per quarter`;
// buildRows: when s.review_capacity_exceeded, mark the 2x campaign_markets cell
// { text: `${formatValue(...,'int')} (not achievable: over capacity)` } and the change cell 'n/a: over capacity',
// mirroring brief_to_live.
```
Update `test/model.test.js:220` so it asserts that the over-capacity summary does not contain "live per quarter".

## Warnings

### WR-01: "In market per quarter" is a yearly launch count divided by four, not a count of what is in market

**File:** `site/js/calc.js:110-111`; labels at `site/js/model.js:121`, `site/js/svg.js:18`, `site/index.html:68`
**Issue:** `campaign_markets_per_quarter = campaign_markets_per_year / 4` is an average launch rate. The labels "in market per quarter" and "live per quarter", and the s01 definition "one campaign live in one market counts as one", describe a stock of live campaign-markets. That number depends on how long each campaign runs, which the model has no input or assumption for. If a campaign runs for two quarters, the in-market count is twice the stated figure. If it runs for half a quarter, it is half. The 2x ratio survives, but the absolute 50 and 100 shown with a Modelled chip are mislabelled.
**Fix:** Rename the metric to "campaign-market launches per quarter" in RESULT_ROWS, the svg PANELS, the claims units and the s01 copy. Or add a graded `campaign_duration_quarters` assumption and compute the in-market stock from it.

### WR-02: "Flat headcount" is a headline claim the model never checks

**File:** `site/index.html:33`, `site/index.html:68`, `site/index.html:121`; `site/js/data.js:579`; `site/js/calc.js:9-17`
**Issue:** The answer, the s01 definition and "What 2x does not mean" now all say "within a flat total marketing budget and flat headcount". This phase removed `marketing_fte` from `POSITIVE_INPUTS`, and it now feeds no output except the one-off change cost. Nothing in the model tests whether 120 marketers can run 1.41x the campaigns and produce 1.41x the master concepts (2x on the "More campaigns" route). Only reviewer capacity is modelled. `asm-marketing-fte` says it "is used for the flat-headcount statement", but no calculation backs that statement. The page presents an unmodelled assertion next to graded figures.
**Fix:** Either model marketer capacity, for example as master concepts per marketing FTE per year (a graded assumption plus a utilisation row), or soften the copy to "flat reviewer headcount". Then add an explicit Speculative assumption saying marketing headcount is held flat by assertion and not modelled.

### WR-03: Marketing FTE is no longer validated, so the scenario rows accept negative or NaN values

**File:** `site/js/model.js:213-215`, `site/js/calc.js:9-17`, `site/js/fields.js` (COMPUTE_FIELD_TO_KEY)
**Issue:** `marketing_fte` was dropped from `POSITIVE_INPUTS` and from `COMPUTE_FIELD_TO_KEY`, but `scenarioOutcomes()` still computes `oneOff = change_cost_per_fte * (values.marketers + values.reviewers)`. The UI's `coerce()` guards the field, but the model API no longer does. `scenarioOutcomes({...d, marketers: -50}, ctx)` returns `ok: true` with a one-off change cost of `-$114,000`. `marketers: NaN` returns the misleading "These inputs are too large to calculate." with `key: null`, so no field is highlighted. The test suite now asserts `run({..., marketers: 0}).ok === true`, which locks in the gap.
**Fix:** Validate `values.marketers` in `scenarioOutcomes`, or in `run()`, with an error keyed to `marketers`:
```js
if (!(Number.isFinite(values.marketers) && values.marketers > 0))
  return { ok: false, errors: [{ key: 'marketers', message: 'Marketing FTE: enter a number greater than 0.' }] };
```

### WR-04: The old "approved-live" wording survives next to the new "approved", including inside the same figure

**File:** `site/index.html:160`, `site/index.html:411`, `site/index.html:534`, `site/index.html:627`, `site/index.html:1082`; `site/js/data.js:867`; `test/page.test.js:934`
**Issue:** The phase renamed the metric to "cost per approved asset" in RESULT_ROWS, the svg panels, the maths and s02. Leftovers remain:
- Figure 1's cost panel label (line 160) still reads "Cost per approved-live asset", while the same figure's `<title>` and `<desc>` say "cost per approved asset".
- The sensitivity table header (line 1082) says "Cost per approved-live asset" above live cells computed from the row now labelled "approved asset".
- s07 (line 534) says "derived variants (internal throughput, not the claim), is 40,000 Modelled approved-live variants". That calls internal throughput "live", against the reframe's own guard text.

`test/page.test.js:934` asserts that "cost per approved-live asset" is present, so the inconsistency is locked in by a test.
**Fix:** Replace "approved-live" with "approved" at these sites, including the `matrix-approved` unit in data.js. Update the s08 test word list. Add a page guard: `assert.ok(!/approved-live/i.test(guardText(html)))`.

### WR-05: The default route silently overrides any `campaign_growth_share` other than 0, 0.5 or 1

**File:** `site/js/model.js:15-18`, `site/js/model.js:57`
**Issue:** `defaultRoute()` returns `'both'` whenever `asm-growth-route` is not exactly one of the three ROUTE_SHARE values. `toCompute()` then maps `'both'` to `0.5`. If the register value is ever edited to, say, 0.25, the static page claims computed by `compute(defaultInputs, defaultAssumptions)` use 0.25 while the live calculator defaults use 0.5. The page and the calculator then disagree with no error. I confirmed it: with share 0.25, `defaultValues().route` is `'both'` and `toCompute` gives 0.5. The crosscheck check (`routeChecked[0] !== dv.route`) compares against the same fallback, so it cannot catch this.
**Fix:** Make the mismatch fail loudly. In `defaultRoute`, throw (or have crosscheck fail) when `ROUTES.find(...)` returns `undefined`. Or derive the radio set from the registered value instead of falling back to 'both'.

## Info

### IN-01: `serialiseHash` writes `route=undefined` when values lack a route

**File:** `site/js/state.js:103`
**Issue:** `values.route !== defaults.route` is true when `values.route` is `undefined`, so the function writes `#s11?route=undefined`. I confirmed this with `serialiseHash(valuesWithoutRoute, ctx)`. `parseHash` then reports a "How you get to 2x" notice. `ui.read()` always sets the route today, so this is latent.
**Fix:** `if (ROUTES.includes(values.route) && values.route !== defaults.route) parts.push(...)`. Apply the same guard in `changedCount`.

### IN-02: Cost per campaign-market is always a fixed multiple of cost per approved asset

**File:** `site/js/calc.js:151`, `site/js/model.js:124`, `site/index.html` s02 and Figure 1
**Issue:** `V = campaign_markets × concepts_per_campaign × formats_per_market`, so `cost_per_campaign_market = cost_per_asset × concepts × formats`, and its % change is always identical to cost per asset's. The s02 prose says so ("it moves with cost per approved asset"). The results table, Figure 1 panel and maths step still present it as a separate outcome, which a reader may take as corroboration.
**Fix:** Keep it as a unit translation, but label it "the same saving expressed per campaign-market" in the table and figure, or drop its separate change column.

### IN-03: Duplicate ids in OUTPUT_DEPS lists

**File:** `site/js/model.js:84`, `site/js/model.js:88-89`
**Issue:** `COST` lists `'asm-markets'` and `'asm-growth-route'` both explicitly and through `VOLUME`. `UTIL` lists `'asm-markets'` and then spreads `VOLUME`, which contains it again. This is harmless for `weakestGrade`, but it makes the "most influential first" ordering harder to audit.
**Fix:** Deduplicate with `[...new Set([...])]`, or drop the explicit repeats.
