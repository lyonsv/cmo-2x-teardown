<interfaces>
New contract (from RESEARCH Pattern 1, binding):
- `variantMatrix(concepts, factors)`; concepts integer >= 1; factors non-empty array of `{ id: string, label?: string, count: integer >= 1, applies: number in [0, 1] }`
- multiplier_i = 1 + applies_i x (count_i - 1); rows[i].variants = concepts x product of multipliers 0..i (cumulative, unrounded floats)
- ok: `{ ok: true, concepts, rows: [{ id, count, applies, multiplier, variants }], total, per_concept }`, total === rows.at(-1).variants, per_concept = total / concepts
- fail: `{ ok: false, errors: [{ field, message }] }` (same shape as compute()); never throws; never returns NaN or Infinity. Field names: 'concepts', 'factors', `factors[i].count`, `factors[i].applies`, `factors[i].id`.

Default factor set (golden): sizes 10/1, channels 5/0.75, locales 6/0.4, audiences 5/0.75, tests 4/0.5, feeds 4/0.5 with 4 concepts gives rows [40, 160, 480, 1920, 4800, 12000], total 12,000, per concept 3,000.

From site/js/calc.js: `export function compute(inputs, assumptions)`; compute(defaultInputs(), defaultAssumptions()).baseline.variants_per_year = 40000; defaultInputs().campaigns_per_year = 40.
From site/js/data.js: `defaultInputs()` reads kind 'input', `defaultAssumptions()` reads kind 'model'; new matrix assumptions use kind 'matrix' so neither picks them up.
From test/data.test.js: "derived claims equal compute()" iterates claims with `derived`; matrix claims use a `matrix` field instead, so that test skips them.
</interfaces>
