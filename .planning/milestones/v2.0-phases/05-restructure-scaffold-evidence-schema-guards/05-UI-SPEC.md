# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5, written to also govern the v2 page structure used by Phases 6-10. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Source of truth for visuals is the existing `site/assets/style.css`. This contract adds NO new design system: it reuses existing tokens and patterns and specifies a small number of additive classes. Items marked **[judgement]** were decided without author input (author away) and are open to override.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-written HTML/CSS; shadcn gate not applicable, project is a static editorial page, CLAUDE.md forbids frameworks and Tailwind) |
| Preset | not applicable |
| Component library | none (bespoke classes in `site/assets/style.css`) |
| Icon library | none (text labels only; no icons introduced) |
| Font | System stacks already in `:root`: `--serif` (Iowan Old Style / Palatino / Charter / Georgia) for body and headings, `--mono` (ui-monospace / SF Mono / Menlo) for labels, numbers, chips. No web fonts. |

Constraints inherited from the project: CSP forbids inline script and inline `style=`; no new runtime dependencies; every new element must be reachable without colour alone.

## Spacing Scale

Existing tokens in `:root`, reused unchanged (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--s-xs` | 4px | Chip and flag vertical padding, inline gaps |
| `--s-sm` | 8px | Compact spacing, chip horizontal padding, dl row gap |
| `--s-md` | 16px | Default spacing, grid column gap, TOC row padding |
| `--s-lg` | 24px | Panel padding, `.sec-head` bottom margin |
| `--s-xl` | 32px | Section top margin and padding |
| `--s-2xl` | 48px | TOC margins, appendix divider top margin |
| `--s-3xl` | 64px | Page bottom padding, masthead top padding |

Exceptions: the existing 64px (32px at <=720px) number column in `.sec-head`, `.toc a` and `.claim`; 48px minimum touch target on `.toc a`, `.btn`, inputs, `details summary` (existing). Appendix letters (A-F) use the same 64px column, so no new width is introduced. No other exceptions.

## Typography

Existing roles, unchanged. Exactly 4 sizes and 2 weights are in use for page chrome (17 body, 12 label, 31 h2, display clamp for h1); h3 reuses 17px/600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (serif) | 17px (16px at <=720px) | 400 | 1.6 |
| Label (mono: kicker, caption, th, chip, flag, sec-num, TOC) | 12px | 600 for chip/th/caption/kicker; 400 for sec-num, TOC, flag, cite | 1.6 |
| Heading h2 (`.sec-head`) | 31px (25px at <=720px) | 600 | 1.15 |
| Subsection h3 | 17px | 600 | 1.6 |
| Display h1 | clamp(34px, 5.2vw, 58px) | 600 | 1.05 |

Weights: 400 and 600 only. No new sizes or weights may be added in Phase 5.

Heading rules for the move (a11y, from CONTEXT):
- Every body and appendix section has one `h2` inside `.sec-head`. Demoted v1 sections (e.g. v1 s01 inside `#opportunity`) become `h3` with the same `id="sNN-h"` and keep `id="sNN"` on their wrapping element. They use the existing `h3` style; they do not get a `.sec-num` or `.sec-head`.
- No heading level may be skipped (h2 then h3 only). A demoted section nested in a parent that has no other h3 is still valid.
- Do not restyle demoted headings to look like h2.

## Color

Existing palette, reused unchanged. Page is a paper-and-ink editorial with one muted colour family for grades.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper` #F4F4F0 | Page background, table cells, sticky matrix header |
| Secondary (30%) | `--paper-2` #EDEDE6 with `--rule` #D5D6CE borders; text in `--ink` #1A1C1B / `--ink-2` / `--muted` #62665F | Legend, callout panels, flags, hovered TOC rows, targeted register row |
| Accent (10%) | `--verified` #17554A | Links, focus rings, Benchmark chip, review strokes |
| Grade colours | `--inferred` #7A5D0F (Modelled), `--low` #7A3B34 (Speculative) | Chips only |
| Destructive | none | There are no destructive actions on this page |

Accent reserved for: body links, `:focus-visible` outlines, the Benchmark grade chip (`.c-b`), review-path SVG strokes. Do not use for appendix dividers, evidence labels, or framing stubs.

**Evidence class labels carry no colour [judgement].** Evidence (observed / benchmark / illustrative / hypothesis) is a different axis from grade (Benchmark / Modelled / Speculative). Giving it colour would create a second colour code that readers would confuse with the grade chips, and CONTEXT requires plain text labels. Render evidence in `--ink` mono 12px text, distinguishable by wording only. Grade chips keep their colour plus text label.

### Section markup pattern

Unchanged from v1. Body sections:

```html
<section id="opportunity" aria-labelledby="opportunity-h">
  <div class="sec-head"><span class="sec-num">01</span><h2 id="opportunity-h">What 2x means</h2></div>
  ...
</section>
```

Appendix sections use the same markup with the letter in `.sec-num` (`A`...`F`). Demoted v1 content:

```html
<div id="s01" class="subsection" aria-labelledby="s01-h">   <!-- or <section>; keep the id on the content wrapper -->
  <h3 id="s01-h">Claim &amp; measurement</h3>
  ...
</div>
```

`section + section` already draws the rule and 32px spacing between sections; nested `<section>` elements inside a parent section must NOT trigger it, so demoted wrappers use `<div>` (or a `section` inside a wrapper that breaks the sibling selector). **[judgement]** Use `<div class="subsection">` with `aria-labelledby`. No new CSS is needed for `.subsection`; it is a semantic hook only, with `margin-top: var(--s-xl)` where two follow each other (see additive CSS).

### Table of contents

Reuse `<nav class="toc" aria-label="Sections">` and `.toc a` rows (64px number column, 48px min height, mono 12px). Structure:

1. Nine body rows (`01`-`09`). Note: CONTEXT says "ten body sections", the id table in CONTEXT lists nine body ids plus appendices; the tenth body entry in the brief (detailed appendices) is represented by the Appendices group. Render exactly the nine ids above, then the group.
2. A group label row: `<p class="toc-group" id="toc-appendices">Appendices</p>` styled like `.steps-h` (mono 12px / 600, uppercase, 0.12em tracking, `--muted`), placed between the two link runs. The nav keeps one `aria-label`; the label is plain text, not a link. **[judgement]** Use a `<p>`, not a list, to match the current flat-anchor TOC.
3. Six appendix rows with letters `A`-`F` in `.n`.

Every TOC `href` resolves to an element id (anchor test). The `?query` form is never used in the TOC.

### Appendix styling

- A visual divider before `#appendix-campaign` only: a `div.appendix-divider` containing a `.kicker`-style label "Appendices" and one `p` sentence: "Supporting depth for the sections above: the 10,000-asset campaign, the review model, the gate, the evaluation harness, the vendor comparison and the source register." Style: `border-top: 2px solid var(--ink)` (same weight as `.masthead` rule), `margin-top: var(--s-2xl)`, `padding-top: var(--s-lg)`. **[judgement: CONTEXT left this to discretion; chosen so the 10-section reading path ends visibly.]**
- Appendix `.sec-head` is identical to body sections; the letter is the only difference. No muted or smaller treatment, because appendices hold the v1 evidence readers will scrutinise.
- Each appendix opens with a one-line "Supports" pointer, using existing `.table-note` mono 12px muted style, linking to the body section it supports (for example "Supports: The economics" linking `#economics`). **[judgement]**

### Framing stubs (`#autonomy`, new leads of `#build`, `#supply-chain`, `#economics`)

- Heading plus one paragraph, body style, max 44em (existing `p` rule).
- The paragraph states the question the section answers and says plainly that the full content arrives in a later release of the page. No numbers, no chips, no `data-fig`.
- Marker: a `.later` pill (existing class: mono 12px, `--paper-2` background, `--rule` border) reading "Detail to follow" **[judgement]**, placed under the paragraph. It is text, not colour-coded. Phases 7-10 remove the pill as each section is filled.
- Stub text must pass the jargon ban-list test.

### Expandable technical depth

Reuse `details.maths` (max 44em, summary mono 12px / 600, 48px min height, focus ring already defined, `display: list-item` marker). Contract for v2:
- Summary text is a verb phrase that names what is inside: "Show the maths", "Show the architecture detail" (same style).
- Closed by default; content inside uses existing `ol.maths-steps`, tables, or figures.
- Never hide a figure, grade chip, or number that is the only statement of a claim; details hold derivations and technical depth only.
- Print: `details` content must print open (existing `break-inside: avoid`; Phase 5 adds no change; later phases ensure open state for print).

### Evidence labels in tables

- New "Evidence" column in the assumptions table and the source register, immediately AFTER the existing grade column, header `Evidence` in the standard `th` mono style.
- Cell content: one of the four lowercase words `observed`, `benchmark`, `illustrative`, `hypothesis`, in mono 12px, `--ink`, using a new `.ev` span (additive CSS below). No border, no background, no colour. For observed rows with a flag, the existing `.flag` follows the label (already the pattern for company-reported / vendor-claimed).
- Tables remain in `.table-scroll` with `role="region"`, `aria-label`, `tabindex="0"`. Adding a column may need raising the existing `min-width` on the assumptions table and register table by 120px; keep print overrides (`min-width: 0`) intact.
- Body grade chips (`.chip.c-b/.c-m/.c-s`) are unchanged.

### Grade key additions

In the existing `.legend` block, below the grade `dl`, add:
- A `dl` or `p` defining four classes. Use the same `.legend dl` grid (max-content / 1fr, stacks at <=480px). `dt` = the class word in `.ev`; `dd` = definition from CONTEXT (observed, benchmark, illustrative, hypothesis).
- One closing sentence in a `.callout`-free plain paragraph: "Nothing on this page is observed for your organisation. The 12-week pilot is what produces observed data." **[judgement on exact wording; meaning is locked by CONTEXT.]**

## Interaction and Accessibility Contract

- Old links: every v1 anchor (`#s01`..`#s15`, `#sNN-h`, figure/table/asm/src ids) must land on the content that held it; no duplicate ids; `section { scroll-margin-top: 16px }` applies to demoted `.subsection` wrappers too (add `.subsection { scroll-margin-top: 16px }` to the `section` rule) **[judgement]**.
- Share links: `#s11?...` parsing is unchanged; the calculator container keeps `id="s11"` inside `#economics`. Do not move focus or re-render on load differently from v1.
- Smooth scroll respects `prefers-reduced-motion` (existing).
- Keyboard: TOC links, `details summary`, `.table-scroll` regions are focusable with the existing 2px `--verified` outline at 2px offset.
- Evidence and grade are never colour-only: text label present on every row.
- Headings: one `h1`; `h2` per section; `h3` for demoted content; no skipped levels (a11y gate).
- Landmarks: `nav` has `aria-label="Sections"`; the appendix divider is not a landmark and not a heading.
- Print: TOC and skip link hidden; appendix divider prints; tables retain `thead` repeat.
- Contrast: all new text uses existing `--ink` or `--muted` on `--paper`/`--paper-2`, already verified in the a11y gate.
