NEW contracts this plan creates (site/js/state.js; imports ./fields.js and ./model.js only):
- `coerce(field, text)` -> { ok:true, value } | { ok:false, message }. Trim; strip one trailing "%" for pct; accept /^\d+(\.\d+)?$/ or strict thousands /^\d{1,3}(,\d{3})+(\.\d+)?$/; reject everything else ("1e3", "0x10", "NaN", "Infinity", "-3", "1,5", inner spaces). pct: divide by 100 then Number(x.toPrecision(12)), must be <= 1 (yield > 0). int fields must be whole. Zero rejected unless field.zeroOk. Upper bound 1e9. Messages exactly: empty -> "{label}: enter a number."; bad format -> "{label}: use digits only, for example {example}."; below min / not whole / out of range -> "{label}: enter {rule}.".
- `validate(values, ctx)` -> [{ key, message }] cross-field: auto1 <= baseline T0+T1 (0.75), auto2 <= scaled T0+T1 (0.85) from ctx.assumptions.tier_mix; message "Auto-approval share at 2x: cannot exceed {cap}%, the share of assets that can clear without a person (T0 and T1)." (and the "today" equivalent for auto1); then any run() error mapped to its key; a key-null error -> { key:null, message: "These inputs are too large to calculate." }.
- `parseHash(hash, ctx)` -> { values, notices:[labels], restored:boolean }. Only hashes starting "#s11?" are parsed; anything else returns defaults, restored false. Iterate FIELDS (allow-list) and read URLSearchParams.get(key); first value wins; unknown keys ignored; invalid values -> default + label in notices; `scenario` must be one of SCENARIOS.
- `serialiseHash(values, ctx)` -> "" when all values equal defaults, else "#s11?" + non-default keys in FIELDS order then scenario; pct written as whole numbers via Number((v*100).toPrecision(12)).
- `toText(field, value)` -> input display text (pct x100, no thousands separators).
- `changedCount(values, ctx)` -> number of keys differing from defaults.
