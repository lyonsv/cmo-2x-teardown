## Top 3 Priority Fixes

1. **Mobile and wrapping layout of the new long labels is unverified** (WARNING). "Campaign-markets launched per quarter" is a 37-character label in the `.metric-trio` `.lbl`, in the Figure 1 `panel-lbl` and in the live-chart panel. The spec limits Figure 8 labels to 13 characters per line, and Figure 1 panel labels sit in a fixed viewBox. Fix: take a real 375px and 768px capture (Playwright, not headless Chrome `--window-size`) of s01, Figure 1 and Figure 8, and confirm that no label clips or collides with bars. Add a text-fit assertion for the renamed panel label if one is missing.
2. **The "define once in s01, then say campaigns live across markets" rule is not followed** (WARNING). `campaign-markets` appears in the answer, the metric trio, s02, Figure 1, s10 and s11, and the answer paragraph uses it before s01 defines it. A CFO reading only the answer sees an undefined coined term. Fix: add a short gloss in the answer ("one campaign launched in one market") or link the term to s01, and use "campaigns live across markets" in prose outside s01 as the spec states.
3. **Over-capacity state carries meaning in text only and has no visual treatment** (WARNING). `model.js:184` and `svg.js:36` mark the unachievable 2x campaign-markets as a text suffix "(not achievable: over capacity)", and the live-chart bar is labelled "unachievable". The bar is still drawn at full 2x length, so the eye reads a 2x win and the text contradicts it. Fix: render the bar with the existing hatch pattern or a muted fill (reusing the `hatch-*` defs), and give the figure's desc and the results table row a non-colour marker. Check the live region announces the change.

Further fixes:
4. The Figure 1 caption and results table disclose that cost per campaign-market always mirrors cost per approved asset (IN-02). It is still shown as a separate panel and row, which looks like corroboration. Consider folding it into the cost panel as a secondary line.
5. s01 and the answer now carry many inline chips: four in the answer paragraph and one in the s01 flat-headcount sentence. The answer paragraph is dense. Consider moving the cost and brief-to-live chips to the metric trio only.
6. The "Flat marketing headcount is assumed, not tested" paragraph (index.html:122) sits in the "What 2x does not mean" callout but is separate from the three-point list. Confirm it is visually distinct and not mistaken for a fourth "does not mean" item.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Grep for `approved-live`, `in market per quarter`, `live per quarter` and `cycle time` across `site/index.html` and `site/js/*.js` returned 0 hits. The rename in the review Fix Status is confirmed in the shipped files.
- The label "Campaign-markets launched per quarter" is consistent across the trio (index.html:71), Figure 1 (:151), RESULT_ROWS (`model.js:121`) and `svg.js:18`.
- "Brief-to-live time" is used in the trio. The answer paragraph says "Brief to live" without hyphens, a minor inconsistency with the spec rule, which names "Brief-to-live".
- The answer (index.html:33) uses the coined "campaign-markets" before s01 defines it (:68). Spec rule: define once in s01. This is a WARNING for first-time readers.
- The honest-framing copy is good: s01 states it is a launch rate, not a count running at once. The falsifier sentence is intact.
- The over-capacity copy ("cannot go live and brief-to-live time is unbounded") is clear and consistent with s07.
- The spec bars numerals outside data-figs. The s02 prose and answer were not exhaustively checked for numerals. The page tests assert the numeric gate, so this is likely satisfied. Confirm.

### Pillar 2: Visuals (3/4)
- The focal point is unchanged: the answer paragraph, then the trio. The trio uses `.metric-trio` and `.lbl` as the spec requires.
- Figure 1 keeps the data-bar pattern. Segments use `hatch-2/4/6` fills so grade or component is not colour-only.
- Over-capacity state: the bar stays full length, with a text-only "unachievable" note (see priority fix 3).
- The route radio set (index.html:833 to 837) reuses the headcount-scenario fieldset with a `legend`, title and desc spans. This matches the contract.
- No icon-only controls were introduced.

### Pillar 3: Color (3/4)
- No new colour tokens were added, and the phase introduced no hex values in the changed regions (not exhaustively grepped across the 250 KB file).
- Chips follow the grade rules: `c-m` for Modelled, `c-s` for Speculative, `c-b` for Benchmark. Each carries a text label, so colour is never the sole signal.
- Chip density: the answer paragraph holds four chips plus the s01 additions. The 04-UI-SPEC density amendment applies. Confirm the answer paragraph complies.

### Pillar 4: Typography (3/4)
- No new font sizes or weights appear in the changed markup. The new content uses `b`, `.lbl` and existing classes.
- `assets/style.css` declares sizes of 10.5pt (print), 12px, 16px (three rules), 17px (two), 25px, 31px and a clamp for the h1. This exceeds the spec's four sizes. It is inherited from earlier phases and not introduced here, but it deserves a cleanup in a later phase.

### Pillar 5: Spacing (3/4)
- Reuse only. No arbitrary values were introduced in the changed blocks.
- The trio's `.lbl` for a 37-character label wraps to two lines on narrow viewports. The mobile capture suggests the trio cells are narrow, but the capture is unreliable. `needs_human_review`.

### Pillar 6: Experience Design (3/4)
- Good: the over-capacity "not achievable" row and "n/a: over capacity" change cell mirror brief-to-live. The model rejects invalid marketers (WR-03). The route is allow-listed in the hash. `defaultRoute()` throws on drift. 371 tests pass, and 17 smoke checks pass per the review.
- Gap: the over-capacity visual treatment relies on text (see priority fix 3).
- Gap: `asm-flat-marketing-headcount` is Speculative and the page says the model does not test it. That is honest, but the calculator offers no input that lets a CMO test it. The "flat headcount" claim stays in the headline sentence, which weakens the CFO-credibility goal. This is a WARNING and a content decision.
- Gap: the s11 route radios change the headline number. Confirm the live region announces the new results. The spec requires live regions, but I did not verify this announcement in code.
- No registry audit was run. No `components.json` is present.
